# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Hard rule: the app never writes under FM_HOME or `~/.claude`, except `lib/wake.js` appending one line per order to `<home>/state/ship-deck-inbox.status` (append-only, `--no-wake`; add no other FM_HOME write) and `lib/knowledge.js` writing/removing only `<claude-dir>/skills/teammate-*` dirs that carry its `.ship-deck-teammate.json` marker (with `--share`; never another skill dir or a symlink); its other writes are `~/.ship-deck/` (orders, sessions.json, `attachments/`, `share.json`; see `lib/attachments.js` and the README Attachments section). `lib/fleet.js`, `lib/sessions.js` discovery and `lib/activity.js` (first mate transcript tail) only read. The only commands allowed are `tmux list-windows`, `tmux capture-pane` and `<home>/bin/fm-send.sh <window-from-meta> <msg>` (all in `lib/actions.js` / `lib/fleet.js`, execFile, fixed argv; live config sends only `lib/config.js` allow-listed `/effort`/`/model`), plus the startup-only browser opener in `server.js` `openBrowser` (own URL, `--no-open`); add no others (the captain name is parsed from git config files, not `git`). Every other captain action is an order kind in `lib/orders.js`, documented in the README contract table. Tests fingerprint the home and inject the executor - never run fm-send in tests.
- `createServer` defaults `ordersDir`/`claudeDir` to the real `~/.ship-deck` and `~/.claude`: tests and manual runs must pass temp dirs (`--orders-dir`, `--claude-dir`). Home auto-detection (`lib/home.js`) takes an inherited `FM_HOME` first, and firstmate shells export the real one: run manual checks with `env -u FM_HOME` or an explicit `--home`. Anything that spawns the server (start.sh tests, manual runs) passes `--no-open`/`SHIP_DECK_NO_OPEN=1`, or it opens a real browser tab. In a browser against the real home, never click Send/Apply live (they reach real workers). Browser checks: run against a scratch `--orders-dir`; `chrome-devtools-axi` needs `CHROME_DEVTOOLS_AXI_MCP_PATH` pinned to a cached chrome-devtools-mcp 1.6.0 entry file (`…/build/src/bin/chrome-devtools-mcp.js`, not the package dir; set the viewport with `emulate --viewport` together with `--color-scheme`, since an emulate call without `--viewport` resets it) and a named `CHROME_DEVTOOLS_AXI_SESSION` (the default bridge may be another agent's, on another MCP version: "Required at pageId"), and writes screenshots only to temp dirs (copy them into `docs/`); its `eval` takes one expression (wrap statements in an IIFE; long multi-line scripts can fail with "fn is not a function", so pass them as `(0, eval)(atob('<base64>'))`). For a coloured terminal peek, put a `tmux` shim on the server's PATH that runs `tmux -L <lab-socket>` and start a lab session `fleet:fm-alpha-fix`; pane text is rendered only through `public/ansi.js` (class names + textContent, never innerHTML). For the Activity feed, install `test/fixtures/transcript/firstmate.jsonl` (replace `__HOME__`/`__SESSION__`) under a scratch `--claude-dir`. Screenshots for `docs/` show the home path and first-run paths: pin them to neutral text (e.g. `~/firstmate`) before capturing; never commit a real name or path.
- POST routes must keep the Host/Origin/`X-Ship-Deck` guards in `server.js`; clients send crew ids or library keys, never paths or tmux targets.
- Sharing (`--share`, off by default) is the only network egress: `lib/share.js` pushes an allow-listed, `lib/redact.js`-scrubbed projection to the relay over HTTPS and treats every relay answer as data. It must never require orders, wake or actions (`test/share.test.js` checks its imports; terminal text comes in through an injected `readTerminal`). New snapshot fields go in both `WORKER_KEYS`/`SNAPSHOT_KEYS` and `relay/lib/snapshot.js`. Grant scopes `skills`/`notes` also push full text as a separate library (`projectLibrary` -> `POST /v1/library`, allow-list re-applied in `relay/lib/library.js`); a teammate's own deck syncs it over its deck token (GET-only `/v1/knowledge`, versioned by `kver:<sub>` so unchanged checks are ~free) into teammate skills (`lib/knowledge.js`, `test/knowledge.test.js`), and agents without Ship Deck may read it with agent keys on GET-only `/v1/agent/*` (`docs/AGENT-LIBRARY.md`); keep both free of write routes, and never re-share `skill:teammate:*` entries. `relay/` is a separate zero-dependency Vercel project (README there: deploy, env, free-tier budget asserted in `relay/test/relay.test.js`); its `public/style.css`, `board.js`, `markdown.js` are copies refreshed with `node relay/scripts/sync-ui.js`, and symbols shared with `public/index.html` must stay identical. Viewer pages run under a CSP with `script-src 'self'`: no inline scripts. Manual checks: `node relay/dev.js --port <p> --invite you@keychain.com` (memory store) plus `ship-deck --share --share-relay http://127.0.0.1:<p>` with scratch dirs.
- UI system: the "Chart room" tokens at the top of `public/style.css` (the `prefers-color-scheme` dark block and `[data-theme="dark"]` must stay identical; `test/contrast.test.js` checks both and AA for every text pair). Status anywhere is a signal flag + tone + word from `public/board.js` (`statusOf`, `groupBoard` for the Board, tested in `test/board.test.js`); add new states there, not inline colours. Icons and flags are `<symbol>`s in `index.html` used via `icon()`/`flagEl()` in `app.js`; no emoji. Board cards are keyed and rebuilt only when their signature changes, and nodes are moved only when out of place, so focus and typed drafts survive the 3 s poll; keep that when adding card content.
- Zero dependencies, no build step: `node server.js` (or `bin/ship-deck.js`, the npx entry) to run, `npm test` (node:test) to test. UI copy is plain language (`public/labels.js`, README "Words on screen"); API fields, order kinds and files keep firstmate's names. See README.md for flags and data sources.
- `bin/install.sh` (per-person install for teammates, guide in `docs/TEAMMATE-SETUP.md`) is separate from the app's write rules: it writes `~/.ship-deck/app` and `~/.local/bin/ship-deck`, and only with `--autostart`/`--edit-path` a LaunchAgent/systemd unit/shell rc line; never sudo, never clones firstmate. Run it only with a temp `HOME` and shimmed `launchctl`/`systemctl`/`uname` (see `test/install.test.js`); the app files it copies are the `package.json` `files` set plus `docs/`.
- Never test against the real fleet home by modifying files; copy `test/fixtures/home` (fabricated data only, never real fleet records) to a temp dir and point `--home` at it.
- Real fleet data drifts: status lines may carry a timestamp prefix or `[key=...]`, `project=` paths differ in case, and status logs contain stray shell output. Keep parsers loose and add a fixture case when a new shape appears.
